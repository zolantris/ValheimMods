# Anchor integration checks

These files belong in a separate BepInEx test host. Do not compile them into the production mod or run them in a normal world.

They require the private host, installed game/Unity assemblies, Steam, and a live dedicated server/client. They are not standalone unit tests and do not run in CI. Install `AnchorWriteObserver` before loading any world so restart checks can detect state or snapshot setter calls from startup onward.

The host must enforce an isolated save directory, a disposable character, localhost networking, and exclusive test execution. Supply a result callback that retains every check and failure. Flatten nested enumerators and dispose them on failure so their cleanup blocks run.

1. Install the native build on both the dedicated server and client, without the standalone anchor addon or temporary patch.
2. Put `HorizontalLock = true` and `VerticalLock = false` in the server's `[Anchor]` section. Put the opposite values in the client file before launch. Confirm the connected client's runtime values follow the server before fixture overrides begin.
3. Run `AnchorIntegrationChecks.Run`. Its marked boat is separate from earlier lab boats. The suite covers position persistence, all position-lock combinations, legacy snapshot migration, physical motion, release, loading, teleport/hauling suspension, controlled replication timing, and actual zone unload/reload.
4. Create `keep-raft-fixture` in the run directory to retain the fixture for subsequent checks. The suite stores its unique marker and expected pose in `anchor-restart.json` in the parent directory.
5. Run `AnchorHelmChecks.Run` before the restart suite. It adds a temporary floor and wheel, uses real wheel interaction, injects key-down/key-up into the actual anchor handler, and waits for physical animation completion. Queue checks explicitly hold the handoff flag on an already owned ship to test coalescing, cancellation, expiry, and subsequent fresh input. They do not simulate a real multiplayer ownership transfer or deliberately suppress RPCs. Wheel retries allow the upstream five-second takeover timer to finish. The final actual anchor drop updates the expected restart pose, since raising and lowering can change the parked location.
6. Save and stop both processes. Restart the same disposable world, then run `AnchorIntegrationChecks.RunRestart`. It checks fresh process IDs, the saved boat pose/state and anchor geometry, then releases and removes the marked fixture.

The main suite's remote replication checks temporarily change only the fixture's local ZDO ownership/state and call the actual synchronization method. They establish method behavior under controlled inputs, not latency behavior with multiple human clients. The vertical-motion check uses repeated upward impulses with boat collision detection temporarily disabled, then restores it. Native movement and synchronization remain active; this establishes that Y is free, not ocean wave amplitude. Wooden anchors are exercised; other anchor prefabs and full modpacks require separate coverage. Protect the disposable character from fall damage before fixture work, and reject an already dead player.

The host should record the native DLL's SHA-256, game/mod versions, result counts, exceptions, and build revision. Keep local account identifiers and raw personal logs out of published results.

Review follow-up coverage adds mirrored-state write protection, exact constraint restoration, same-frame hold idempotence, remote sleeping, persistent anchor deletion with one/two anchors and replacement, and open-water observations. The open-water phase uses 150 seconds per ocean-sway setting with normal collisions and floatation. Its measurements, rather than the earlier impulse test, establish whether the boat is floating and moving vertically. The non-owner helm case observes the normal dispatch method boundary with its network send intercepted; it does not establish a real two-client ownership transfer. The restart phase observes for 30 seconds and checks that no anchor state or snapshot setters ran for the retained fixture.

The next correction pass places the live water fixture beyond 4 km from the centre but within 8.5 km of it. Each water sample is compared with the fixed saved position/rotation keys, starting immediately after the sway toggle. A separate same-frame check injects one-ULP position error at large coordinates, verifies sleeping, then verifies correction of a 2 cm displacement. That numerical check restores the boat before yielding; it does not exercise or change the world's edge waterfall or falling behavior.

Pending-removal checks use real anchor prefabs and persistent deletion, with the second anchor held in a controlled pending list/queue. An additional hook check forces the initial-activation flag without deleting a piece. Geometry boundary checks position the real wooden anchor at a controlled 25-degree pitch and 15-degree roll with -0.5, 0.5, 1, 2, 2.01 and 45 m ground clearance. They exercise final placement and body alignment, not the drop animation's endpoint. The restart check explicitly claims the ship, records ownership on every physics sample for 30 seconds, calls the actual hold, and requires no state/snapshot setter calls since process startup. It does not establish who owned the ship before the claim or observe server-side setters.

`RunStorm` uses the retained fixture before its final restart check. Its private-host weather callback forces ThunderStorm and wind intensity 1.0, then restores the previous environment and debug-wind settings in a finally block. The server must use the same weather and retain sampled confirmation independently. Two 150-second phases use free height with ocean sway on/off; a 30-second phase enables the height lock. Each checks real water-level variation, saved-reference drift, rotation, body state and ownership. The fixture has no deployed sail, so ambient maximum wind is not evidence of deployed-sail wind load. Preserve the fixture for a fresh process restart afterward.
